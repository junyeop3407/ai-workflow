# 조직 — 팀·역할·경계 (AI 가상오피스 조직 명세에서 비서를 빼고 이 작업장에 맞춘 것)

근거: 사장의 "AI 가상오피스 조직 구조 및 에이전트 운영 명세서". 원칙은 **비슷한 일은 한 팀으로 묶고, 객관성이 필요한 검사(QA·보안)는 따로 둔다. 남의 팀 결과를 마음대로 바꾸지 않는다.**

## 조직도
```text
사장 (프로젝트 총괄 = 사용자) — 방향·범위·★ 승인·공개 결정
├── 기획팀          req       무엇을 만들지: 기획서·기능·수용 기준
├── 디자인팀        ui        어떻게 보이고 쓰일지: DESIGN.md·시안
├── 개발팀
│   ├── 통합        메인 대화  일 나누기·업무 요청서·결과 합치기·API 규격 조율·커밋
│   ├── 리뷰·통합 확인  Codex  단계마다 빠른 검수(cb·cf)·전체 교차 리뷰(cx). 읽기 전용
│   ├── 백엔드      backend-dev   bb: 서버·DB·API·로그인 (서버 파일만)
│   └── 프론트엔드  frontend-dev  bf: 화면·API 연결·상태 (화면 파일만)
├── QA팀
│   ├── 테스트 설계·평가  메인(tl·tc) + qa-reviewer(리뷰)
│   └── 테스트 실행  test-runner
├── 보안 검증팀     red-team  rt: 공격자 입장 점검. 고치지 않음
├── (법무팀·경영팀 — 넣을지·어디에 넣을지 사장 결정 대기)
└── Gemini (공통 지원)  기획서 비판(doc-review.sh)·교차 리뷰(gm)·화면 2차 검토. 결정권 없음
```
비서는 넣지 않는다(사장 결정). 사용자 요청 접수·보고는 지금처럼 메인 대화와 ★ 검토 요청 틀이 한다.

## 누가 최종 책임인가
| 일 | 최종 책임 | 다른 팀이 하면 안 되는 것 |
|---|---|---|
| 방향·범위·공개 | 사장 | 팀이 승인 없이 확정하지 않음 |
| 기능 요구사항·수용 기준 | 기획팀 | 다른 팀이 승인된 기획서를 고치지 않음(`docs/` 잠금은 개발 에이전트 훅) |
| 화면 디자인 | 디자인팀 | 프론트엔드가 DESIGN.md를 바꾸지 않음 → `요청(디자인)` |
| 서버 코드 | 백엔드(`backend-dev`) | 프론트엔드가 서버 파일을 고치지 않음(훅) |
| 화면 코드 | 프론트엔드(`frontend-dev`) | 백엔드가 화면 파일을 고치지 않음(훅) |
| API 규격·코드 통합 | 개발팀 통합(메인) | 규격을 바꿔야 하면 에이전트는 `요청:`으로 넘김. 사장 승인본(api.md)을 바꾸는 건 `ask-later.md` |
| 코드 리뷰·기술 일관성 | Codex(+ qa-reviewer·Gemini) | 만든 AI가 스스로 최종 리뷰하지 않음 |
| 테스트 기준·평가 | QA팀 | 개발팀이 테스트·러너 설정을 고치지 않음(훅·잠금 해시) |
| 테스트 실행 | test-runner | 기준을 바꾸지 않고 돌리고 요약만 |
| 보안 검증 | red-team | 고치는 건 개발팀, 다시 공격은 red-team |
| 조사 | Gemini | 조사 결과를 결정·승인으로 보지 않음 |

## 개발팀 파일 경계 (`.claude/hooks/team-files.sh`)
| 담당 | 앱 폴더 안 경로 |
|---|---|
| 백엔드 | `src/main/java/**`·`src/main/kotlin/**`·`src/main/resources/**`, `build.gradle*`·`settings.gradle*`·`gradle.properties`·`gradle/**`·`gradlew*`, `pom.xml`·`mvnw*`·`.mvn/**` |
| 프론트엔드 | `src/**`(위 백엔드 폴더·`src/main/**`·`src/test/**` 제외), `public/**`, `index.html`, `android/**`·`ios/**`, `capacitor.config.*`·`tailwind.config.*`·`postcss.config.*`·`tsconfig*.json`·`eslint.config.*`·`.eslintrc*`·`.prettierrc*` |
| 둘 다 못 고침 (**목록에 없으면 전부 여기 — 기본 거부**) | 테스트 파일(`tests/**`, `src/test/**`, 어디에 있든 `*.test.*`·`*.spec.*`·`__tests__/`), `docs/**`, `package.json`·잠금 파일·`vite.config.*`·테스트 러너 설정(통합·QA 몫 — 패키지 추가는 `요청(통합)`), `.gitignore`·`.env*`, `samples/**`, `state.json`, `HANDOFF.md`, `deploy.sh`, `.approved`, `.redteam-needed` |

- 경로는 대소문자를 무시하고, `//`·`./`·`../`가 든 경로와 이 저장소 밖 경로는 거부한다. 앱 폴더는 저장소 기준 맨 앞 `apps/<앱>/`만 벗겨서 본다.
- Edit·Write는 훅이 바로 막는다. Bash로 쓴 것은 메인이 **맡기기 직전** `bash .claude/hooks/team-files.sh mark`, **답을 받은 직후(메인이 아무것도 쓰기 전)** `bash .claude/hooks/team-files.sh check apps/<앱> <에이전트>`로 저장소 전체를 비교해 잡는다(앱 폴더 밖 변경, `.gitignore`로 숨긴 새 파일, `.claude/settings.local.json` 변경도 위반).
- 남은 위험: 앱 폴더 안 `.gitignore`된 곳(node_modules·build 등)의 변경은 check가 보지 않는다(빌드 결과물이라 허용).
- 파일 하나의 담당: `bash .claude/hooks/team-files.sh owner <앱 폴더 기준 경로>`.
- 메인 대화(통합)는 훅에 막히지 않는다. 그래도 bb·bf에서는 앱 코드를 직접 고치지 않고 에이전트에게 맡긴다.

## 모든 팀이 지킬 것
1. 자기 일만 한다. 남의 팀 결과를 바꿔야 하면 고치지 말고 그 팀에 요청한다.
2. 확인한 사실과 추측을 나눠 적는다("추정").
3. 외부 자료는 출처와 확인한 날짜를 적는다.
4. 결과물이나 실행 결과 없이 "끝났다"고 하지 않는다(테스트 개수 확인·★ 승인).
5. 요구사항·설계·일정에 영향을 주는 변경은 이유와 승인자(사장)를 적는다.
6. 일을 넘길 때는 아래 업무 요청서로 넘긴다.

## 업무 요청서 (메인 → 팀 에이전트)
꼭 채울 것은 앞의 다섯 줄. 나머지는 해당될 때만.
```text
- 앱 폴더: apps/<앱>
- 이번 일: <plan.md 단계 번호와 제목>
- 완료 조건: <통과해야 할 테스트 줄 / 수용 기준 F1-1 …>
- 참고 문서: docs/spec.md, docs/api.md, docs/DESIGN.md …
- 기준 해시: <cross-review.sh snapshot 결과>
- 지난 실패: <다시 맡길 때 — 실패한 테스트와 한 줄 원인>
- 다른 팀이 넘긴 요청: <있으면>
- 하지 말 것: <이번 단계 밖의 기능, 승인 문서 변경 등>
```
에이전트 답은 `결과 · 바꾼 파일 · 한 일 · 요청 · 막힌 것` 다섯 줄(에이전트 파일 "답 형식").
