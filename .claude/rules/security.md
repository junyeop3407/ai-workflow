# 보안 규칙 (서버 분리 · 암호화 · 인프라)

바이브코딩으로 빨리 만든 앱에는 보안 구멍이 최소 한 개는 있다고 보고 만든다. 서버가 없는 앱은 1번의 "프론트에 비밀값 금지"만 지킨다.

## 1. 서버 분리
- 비밀 키, 결제·인증 로직, 금액 계산, 권한 판단은 백엔드(Spring)에만 둔다. 프론트(React·Capacitor 앱)에는 절대 넣지 않는다. 앱 파일은 누구나 열어볼 수 있다.
- 모든 입력은 서버에서 다시 검증한다. 프론트 검증은 편의용일 뿐이다.
- 모든 API는 "요청한 사람이 이 데이터의 주인인가"를 서버에서 확인한다(남의 ID로 조회·수정 차단).

## 2. 암호화
- 비밀번호는 단방향 해시(BCrypt)로만 저장한다. 평문 저장 금지.
- 주민번호·연락처·업무상 비밀 같은 민감정보는 양방향 암호화로 저장하고, 키는 `.env`에 둔다(`.env`는 커밋하지 않고 `.env.example`에 이름만).

## 3. 인프라
- DB는 외부 접속을 막는다(`0.0.0.0/0` 전체 허용 금지).
- 파일 저장소(이미지 등)는 공개 범위를 정해 기획서에 적는다.
- 서버 접근은 필요한 곳(포트·주소)만 연다.
- 인프라 설정은 AI가 혼자 정하지 않는다. 무엇을 열고 닫는지 쉬운 말로 설명하고 사장에게 확인받는다.

## 배포 전 레드팀 공격
- 6단계 QA 보고 전에 `red-team` 에이전트가 **실행 중인 앱을 직접 공격**한다(절차는 `/build-app` "레드팀 공격"). 코드를 읽는 security-audit·교차 리뷰와 별개다.
- QA 보고에 "보안 점검: 서버 분리 ✓ / 암호화 ✓ / 인프라 ✓ · 레드팀에서 찾은 구멍 N개 → 고침"을 넣는다.
