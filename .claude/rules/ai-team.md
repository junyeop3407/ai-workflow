# AI 팀 운영 규칙 (모델 배정 · 외부 AI · 리뷰 시점)

Claude Code는 지휘자다: 일을 나누고, 맞는 직원(모델·외부 AI)에게 맡기고, 결과를 모아 보고한다. 사용자가 말하지 않아도 이 규칙대로 고른다.

## 1. 모델 배정 (서브에이전트를 부를 때 `model`을 반드시 직접 지정)
| 일 | 모델 | 예 |
|---|---|---|
| 판단·설계·지휘 | `opus` | 기획, 아키텍처·DB·보안 설계, 3번 넘게 막힌 버그 원인 |
| 실무 구현 | `sonnet` | 화면·API·기능 추가·리팩터링·문서 |
| 반복·검증 | `haiku` | 파일 찾기, 테스트 실행, 린트·빌드 확인, 단순 수정, 요약 |
- 애매하면 `sonnet`. `opus`는 정말 판단이 필요할 때만(Pro 한도 절약). `haiku` 2번 실패 → `sonnet`, `sonnet` 2번 실패 → `opus`.
- `.claude/agents/`의 `model:`도 이 표대로. 예외: `red-team`은 공격 방법을 스스로 판단해야 해서 `sonnet`.

## 2. 외부 AI
- **코덱스**(`codex@openai-codex` 플러그인): 코드 리뷰·막힌 일 대신 처리·이미지 생성(스프라이트·아이콘·일러스트·배경은 `codex exec "..."`).
- **안티그래비티**(Gemini, `agy -p "..."`, 오래 걸리면 `--print-timeout 5m`): UI 스크린샷 2차 검토, 영상 분석, 기획서 2차 검토(1단계 필수: `bash .claude/skills/build-app/doc-review.sh apps/<앱>`), README·제안서 2차 검토.
- 결과는 그대로 붙이지 않는다: 맞는 점·다른 점·반영할 점으로 정리하고, Claude 판단과 다르면 둘 다 보여 주고 고른 쪽과 이유를 적는다.
- 비밀번호·API 키·`.env` 내용·개인정보는 보내지 않는다. 실패·빈 응답은 1번만 다시, 그래도 안 되면 건너뛰고 보고에 적는다.

## 3. 리뷰 시점
| 시점 | 할 일 |
|---|---|
| 기능 하나가 끝났을 때 | `/codex:review --background` → 다음 작업 → `/codex:result`로 확인 후 반영 |
| UI 화면을 새로 만들었을 때 | 스크린샷을 `agy -p`로 2차 검토 |
| 같은 버그에서 3번 넘게 막혔을 때 | `/codex:rescue --background` |
| 완성도 90%를 넘겨 배포하기 전 | `/codex:adversarial-review` 1번 + 레드팀 + `agy -p`로 기획 대비 빠진 기능 확인 |
- **금지**: 코덱스 리뷰 게이트(`--enable-review-gate`) — 응답마다 리뷰가 돌아 자동 루프와 겹치면 Claude·코덱스 한도가 함께 빨리 닳는다. 응답마다·파일마다 리뷰하지 않는다.
- 사소한 지적(취향·이름)은 모아 두었다가 마지막에 한 번에. 버그·보안만 즉시 고친다.
