# 2단계 설계 (opt·ok-opt) — 이 노드에 들어갈 때 읽는다. "참고 디자인 분석"은 4단계 디자인팀(ui)도 쓴다

- 설계안 3개는 CLAUDE.md "팀별 기본 기술" 안에서, **쉬운 것(설치 적음)부터**, 각 안에 테스트 도구·설치 필요 여부·장단점·추천. 화면이 있으면 디자인 방향 보기 2~3개(참고 디자인 분석을 거쳐서). 추천안은 사전 부검. 고른 안·버린 안과 이유·테스트 도구를 `docs/design.md`에.

## 설계안 점수표 (2단계)
설계안 3개를 글로만 설명하면 초보 사장은 고르기 어렵다. 같은 기준으로 점수를 매긴 표를 함께 보여 준다.
| 기준 (가중치) | 무엇을 보나 |
|---|---|
| 시작 쉬움 (×3) | 새로 설치할 것, 사장이 직접 해야 할 일의 수 |
| 고치기·늘리기 쉬움 (×2) | 나중에 기능을 더하거나 다른 컴퓨터에서 이어 하기 쉬운가 |
| 돈 (×2) | 서버·서비스 월 비용 (0원이면 5점) |
| 꼭 되어야 할 기능 (×3) | 1단계 기획서의 우선 기능을 무리 없이 다 하는가 |
- 각 기준 1~5점 × 가중치 → 합계(최고 50점). 표 맨 아래에 합계와 **추천 1개 + 한 줄 이유**를 적는다.
- 가중치는 이 앱에 맞게 바꿔도 된다(예: 혼자 쓰는 도구면 돈 ×3). 바꿨으면 왜 바꿨는지 한 줄 적는다.
- 점수는 Claude의 추정이다. 근거가 약한 점수에는 "(추정)"을 붙이고, 점수가 비슷하면(3점 이내) 비슷하다고 말한다. 점수로 밀어붙이지 않는다.
- 고른 안과 표를 `docs/design.md`에 남긴다.

## 참고 디자인 분석 (2단계 디자인 방향, 4단계 디자인팀)
"토스 느낌"처럼 참고할 서비스가 있으면 따라 하기 전에 먼저 나눠서 본다.
| 칸 | 무엇 | 예 |
|---|---|---|
| 유지할 것 | 이 앱에도 맞는 원리 | 한 화면에 할 일 하나, 큰 숫자 강조, 넉넉한 여백 |
| 바꿀 것 | 우리 앱·사용자에 맞게 고칠 것 | 색(우리 색으로), 버튼 문구, 정보량 |
| 베끼지 말 것 | 그 회사 고유의 것 | 로고·이름·고유 일러스트·아이콘 세트·특징적인 색 조합 그대로·문구 |
- 이 표를 `docs/DESIGN.md` 맨 위 "참고" 절에 남긴다. "베끼지 말 것"은 시안·코드에 넣지 않는다.
- 참고 서비스가 없으면 이 절은 건너뛴다(사장이 고른 디자인 방향만 적는다).
