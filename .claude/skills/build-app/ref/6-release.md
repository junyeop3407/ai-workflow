# 6단계 점검·보고·공개 (dv·ex·rt·sa·sc·ok-qa·pub·dep) — 이 노드에 들어갈 때 읽는다

## 6단계 순서와 QA 보고 (ok-qa)
`test-runner`로 통과 확인 → (화면이 있으면) **DevTools 점검**(chrome-devtools-mcp, localhost만: 콘솔 에러·실패 요청 0개, LCP 2.5초·CLS 0.1 이하, 접근성, 폰 크기) → **탐색·사용성 점검**(ok-ip에서 고른 경우만, 다시 묻지 않음) → **완성도 점수**(sc, `graph.sh score`: 필수 관문 + 90%) → (서버가 있으면) **부하 테스트**(`.claude/rules/testing.md` "품질 점검") → **레드팀 공격** → (공개가 필요하면 "올리기") → **QA 보고** → **사장 검토**(써 보고 OK, 수정 지시면 "사장 확인 루프") → **저장소 공개 여부**.

QA 보고(★ 검토 요청 틀로) 맨 위에 **기획서 성공 기준마다 ✓/✗와 근거** + **출시 안내문 대조**(안내문대로 되는지, 안내문에 없는데 만든 것 — 있으면 이유). 그 아래:
- 테스트 N/N 통과, 리뷰에서 찾고 고친 것
- 교차 리뷰 `Codex: 반영 N / 미반영 N(이유) · Gemini: 반영 N / 미반영 N(이유) · 사장 확인 필요`
- "배포 전 체크리스트" 22개 ✓/✗ + 레드팀에서 찾은 구멍 N개 → 고침
- 화면이 있으면 DevTools 점검(콘솔 에러·실패 요청·LCP), 탐색·사용성 결과 또는 "건너뜀(사장 선택)"
- `docs/ask-later.md`의 사장 확인 필요 항목, 실행 방법 한두 줄

## 레드팀 공격 (6단계, QA 보고 전, 필수)
코드를 읽는 리뷰(5단계)와 달리, **해커 입장에서 실행 중인 앱과 코드를 직접 공격**한다. "구멍이 최소 1개는 있다"고 보고 찾는다.
- **언제**: 6단계마다(배포 직전). 앱이면 스토어 심사를 내기 직전에도. 그리고 **`apps/<앱>/.redteam-needed` 표시가 있으면 언제든** — 민감한 파일(로그인·토큰·결제·쿠폰·회원·관리자 등)을 고치면 훅이 자동으로 만든다. 표시가 남아 있으면 QA 보고·배포·`/handoff` 마무리를 하지 않는다.

1. `red-team` 에이전트에게 앱 폴더 경로와 실행 방법만 준다(보안 규칙은 `.claude/rules/security.md`). 에이전트가 정찰(API 주소 목록) → ① 공통 → (모바일 앱이면) ② 앱 파일 기준 → (DB·저장소가 있으면) ③ DB·저장소 → ④ 깊은 공격(토큰 위조·동시 요청·요청 횟수 제한·SSRF·파일 올리기·흐름 건너뛰기) → ⑤ 엮어서 다시 순서로 공격하고, 두 번 재현된 것만 "뚫림", 재현 안 된 것은 "의심"으로 나눠 "위치 / 공격 방법 / 결과 / 증거 / 고치는 방법"을 심각한 순서로 돌려준다.
2. 결과를 `docs/redteam.md`에 그대로 적고, 아래에 찾은 것마다 한 줄: `- [뚫림|의심] [심각|보통] <위치·공격> — 해결: <파일>:<줄>`(아직이면 `해결: 아직`). 심각 = 시크릿 노출·가격/결제 조작·남의 데이터. 해결 안 된 `[뚫림] [심각]`이 있으면 완성도 점수의 필수 관문에서 막힌다.
3. **④ 고치기** (메인 대화에서 이어서):
   - **바로 고칠 것**: 시크릿 키 노출, 가격·결제 조작, 남의 데이터 접근. 나머지는 우선순위를 보고 정해 `NOTES.md`에 남긴다.
   - **고칠 때는 항상 서버에서 막는다.** 클라이언트에 거는 보안은 뜯기면 그만이다.
   - 고치기 전에 그 공격을 재현하는 회귀 테스트를 `tests/test_review_fixes.py`(또는 같은 위치의 회귀 테스트 파일)에 먼저 넣어 실패를 확인하고, 고친 뒤 **같은 공격을 다시 시도**하고 전체 테스트를 다시 돌린다.
   - 노출됐던 키는 코드에서 지우는 것으로 끝내지 않는다. 사장에게 재발급과 옛 키 폐기를 부탁한다.
   - 인프라 설정을 바꿔야 하면 혼자 바꾸지 말고 사장에게 쉬운 말로 확인받는다.
4. 서버가 없는 앱은 ①의 비밀값 찾기·잘못된 입력과 ②만 한다.
5. 뚫린 것을 다 고치고 같은 공격이 막힌 걸 확인했으면 `apps/<앱>/.redteam-needed`를 지운다. 바로 고치지 않고 `NOTES.md`로 미룬 것이 있으면 사장에게 알리고 OK를 받은 뒤 지운다.

### 배포 전 체크리스트 (QA 보고에 ✓/✗로 넣는다. 해당 없으면 "해당 없음")
`docs/checklist.md`에 `| 번호 | ✓ 또는 ✗ 또는 해당 없음 | 근거: <파일>:<줄> |`로 적는다. 어느 노드가 채우는지는 graph.md "배포 전 체크리스트 22개" 표. 근거 줄이 없는 ✓는 점수에서 ✗로 센다.
1. 배포된 사이트·앱에서 `sk-`, `secret`, `service_role`을 검색해도 아무것도 안 나온다
2. 한 번이라도 노출된 키는 재발급했다
3. 가격·할인·배송비는 서버가 계산한다
4. API 주소의 ID만 바꿔서 남의 데이터를 불러올 수 없다
5. 관리자 화면은 서버가 권한을 확인한 뒤에만 내려간다
6. 브라우저에서 DB에 직접 붙어 테이블을 읽을 수 없다
7. 주민번호 같은 민감정보는 암호화해서 저장한다
8. AI 기능에 사용자별 사용 한도가 걸려 있다
9. 레드팀 ①·④(해당하면 ②·③)를 돌리고, 나온 문제를 고쳤다
10. 로그인·인증번호·AI 기능에 요청 횟수 제한이 있고, 토큰을 바꾸거나 만료된 토큰으로는 아무것도 안 된다
11. 쿠폰·포인트·재고·결제 확인을 동시에 20번 보내도 한 번만 처리된다
12. `apps/<앱>/.redteam-needed` 표시가 없다(민감한 파일을 고친 뒤 레드팀을 다시 돌렸다)
13. 결제는 PG사를 쓰고, 서버가 PG사에 결제 내역을 다시 조회해 확인한 뒤에만 주문을 확정한다
14. 회원가입 동의를 필수·선택으로 따로 받고, 선택에 동의하지 않아도 가입된다
15. 화면 하단에 개인정보처리방침·이용약관 링크와 사업자 정보가 있다(문구는 사장에게 받은 것)
16. 연습용 DB와 운영 DB가 나뉘어 있고, 운영 DB는 매일 자동 백업된다
17. 승인된 테스트가 Chrome·Safari 엔진(webkit)·폰 화면 크기에서 모두 통과한다
18. 주요 화면 자동 접근성 검사(axe)에서 심각한 위반이 0개다
19. LCP 2.5초 이하, CLS 0.1 이하, 콘솔 에러 0개다 (화면이 있는 앱)
20. 동시 50명 부하 테스트에서 에러 0%, 응답 99%가 1초 이하다 (서버가 있는 앱, 로컬 기준)
21. 오픈소스·외부 자료 라이선스 고지(고지 화면이나 NOTICE)와 출처 표시가 있다 (법무팀 출시 전 점검)
22. 법무 판정 RED 자료는 안 쓰고, YELLOW 자료는 사장이 고른 조건대로만 쓴다 (법무 해당 없으면 "해당 없음")

## 탐색·사용성 점검 (ex 노드, 선택 — 비용은 ok-ip(계획 승인) 때 미리 묻는다)
Claude가 처음 쓰는 사람처럼 앱을 직접 눌러 보며 테스트 목록에 없는 문제를 찾는다. 화면 캡처를 많이 읽어 사용량이 크므로 **시작 전에 반드시 비용을 알리고 허락을 받는다.**
1. **비용 알리기** (ip가 계산해 plan.md에 적고, ok-ip에서 계획 승인과 함께 한 번): 점검할 흐름(기획서의 주요 흐름) 목록과 함께 아래를 쉬운 말로 알린다. 답은 `graph.sh budget apps/<앱> <예상 토큰>`(건너뛰기 = 0). **ex 노드에서는 다시 묻지 않는다.** 점검 중 실제 사용량을 `graph.sh usage`로 알리고, 예상의 2배를 넘으면 그때만 멈추고 묻는다(④).
   - 예상 사용량: 흐름 수 × 흐름당 단계(클릭) 수 × 단계당 약 3천~5천 토큰(화면 캡처 포함) → 합계 토큰 "(추정)"
   - 예상 금액: 그때 쓰는 모델의 **현재 요금을 확인해서** 계산한다(기억으로 정하지 않는다. `claude-api` 스킬 또는 공식 요금 페이지). 구독(Pro·Max)으로 쓰는 중이면 "추가 요금은 없고, 사용 한도를 그만큼 씀"이라고 함께 말한다.
   - 예상 시간
   - 그다음 ok-ip의 AskUserQuestion에 "진행해 / 흐름을 줄여서 / 건너뛰기"를 함께 묻는다(추천 붙여서).
2. **하는 일** (진행해일 때만, localhost만): 주요 흐름을 브라우저로 직접 해 보며
   - 탐색: 순서를 바꿔 누르기, 뒤로 가기·새로고침·중간에 나가기, 같은 버튼 여러 번 누르기, 이상한 값 넣기
   - 사용성: 다음에 뭘 눌러야 할지 막히는 곳, 헷갈리는 문구, 단계가 너무 많은 곳, 눌렀는데 반응이 안 보이는 곳
   - 알린 예상 사용량의 2배를 넘으면 멈추고 다시 묻는다(④).
3. **결과**: `docs/explore.md`에 "흐름 / 한 일 / 찾은 문제 / 캡처"로 적는다. 버그는 회귀 테스트를 먼저 넣고 고친다. 사용성 의견(문구·배치)은 고치지 말고 QA 보고에 추천과 함께 올려 사장이 정한다.
4. 건너뛰었으면 QA 보고에 "탐색·사용성: 건너뜀(사장 선택)"이라고 적는다.

## 사장 확인 루프 (6단계 사장 검토, 사장 수정 지시를 처리할 때)
- 고쳤다고 끝내지 않는다. 고친 뒤 AskUserQuestion으로 묻는다: **"해결됐어요" / "아직이에요(무엇이)"**.
- "아직이에요"면 그 말을 그대로 `graph.sh fail apps/<앱> ok-qa "<사장 말>" <담당 노드>`의 이유로 삼아 다시 고친다(고친 뒤 테스트 → 다시 ok-qa).
- **같은 지적에 3번 "아직이에요"**면 멈추고 원인(왜 안 맞는지 추정)과 선택지 2~3개(+추천)를 보고한다.
- "해결됐어요"를 받기 전에는 HANDOFF에 "완료"라고 쓰지 않는다.

## 올리기 (친구에게 링크로 보여 줘야 할 때)
- 작업 저장소에는 문서·테스트·기록이 섞여 있으므로 그대로 내보내지 않는다. 앱 파일만 담은 **공개 저장소 + GitHub Pages**를 쓴다(내역은 각자 기기에만 저장되는 앱일 때).
- ★ pub에서 사장이 "올려"를 고르면 **Claude가 직접 실행한다**(dep 노드). Claude Code 안전장치가 외부 공개를 막을 때만 사용자에게 **짧은 한 줄**로 실행을 부탁하고 기다린다(멈춤 ⑤). 긴 명령은 붙여 넣다 줄이 깨지므로 스크립트 파일로 준다.
  - 처음 만들 때: 임시 스크립트로 `gh repo create <앱> --public --source <폴더> --push` + Pages 켜기(`gh api -X POST repos/<계정>/<앱>/pages -f "source[branch]=main" -f "source[path]=/"`) → 다 쓰면 지운다.
  - 다시 올리기: `apps/<앱>/deploy.sh`(상대 경로만, 임시 폴더에 공개 저장소를 받아 앱 파일만 덮어쓰고 푸시, 커밋 이름·이메일은 이 저장소 설정에서 가져옴). Claude가 `bash apps/<앱>/deploy.sh`를 실행한다(막히면 사용자에게 `! bash apps/<앱>/deploy.sh`).
- 올린 뒤 **공개 주소를 직접 열어** 새 버전이 반영됐는지, 핵심 기능이 되는지 확인하고 나서 링크를 준다. 주소와 다시 올리는 방법을 `apps/<앱>/HANDOFF.md`에 적는다.
- `!` 명령은 맨 앞에 띄어쓰기가 있으면 실행되지 않고 메시지로만 간다. 처음 부탁할 때 알려 준다.

## 저장소 공개 여부 (6단계 사장 OK 뒤)
- 새 프로젝트 저장소는 공개로 만들어져 있다. 앱을 다 만들고 사장 OK를 받으면 "이 저장소를 공개로 둘까요, 비공개로 바꿀까요?"를 보기 + 추천과 함께 묻는다(포트폴리오로 보여 줄 앱이면 공개 추천).
- 묻기 전에 코드와 커밋 기록에 비밀값(API 키, 토큰, 비밀번호, 개인정보)이 없는지 확인하고 결과를 함께 알린다.
- 비공개로 바꾸기: 그 폴더에서 `gh repo edit --visibility private --accept-visibility-change-consequences`. 안전장치가 막으면 사용자에게 `!` 한 줄로 부탁한다.
- 고른 결과를 `HANDOFF.md`에 적는다.
